#### Concept 1 — What RNA is (in progress)

RNA is a long, chain-shaped molecule inside cells. Every link in the chain
(a *nucleotide*) has the same repeating *backbone* piece (a sugar joined to a
phosphate). Attached to it is one of four possible *bases*: A (adenine),
U (uracil), G (guanine) or C (cytosine). The backbone carries no information
because it never changes. All the information is in which base sits at each
position. So for our purposes an RNA is a string over the alphabet {A, C, G, U}.
The chain has a direction: one end is called 5′ ("five-prime"), the other 3′
("three-prime"). By convention sequences are written 5′ → 3′, left to right,
so `AUGC` and `CGUA` are different molecules. DNA is the cell's long-term
storage copy of genetic information. RNA is a working copy made from it. Some
RNAs are read to build proteins; others fold into a 3D shape and do a job
themselves. Unlike DNA, RNA is usually *single-stranded*, which is what lets it
fold back onto itself. (Base pairing, next concept, explains how.)

Analogy used: DNA = ROM (master copy, never run from directly); RNA = a
copy loaded into working memory. Sequence = a serial bitstream with a fixed
bit-order convention (reversing it gives a different word).

#### Concept 2 — Base pairing (in progress)

Two kinds of connection hold RNA together. **Backbone links** are strong
(covalent bonds). They are permanent and fix the *order* of the bases.
**Base pairs** are weak (hydrogen bonds). They form and break constantly and
decide the *shape*. Only certain bases pair: **G–C** (3 hydrogen bonds,
strongest), **A–U** (2 bonds), and the weaker **G–U "wobble"** pair. All other
combinations are treated as not pairing. Each base pairs with at most one
partner at a time. A single pair is too weak to survive thermal jiggling; pairs
are stable only in consecutive runs that **stack** on top of each other. When a
strand folds back on itself, the two paired stretches run in opposite
directions (**antiparallel**): in `GGGAAACCC`, position 1 pairs with 9, 2 with
8, 3 with 7. The fold needs at least 3 unpaired bases in the turn (**minimum
hairpin loop = 3**), because the backbone cannot bend tighter than that.

Analogies used: backbone = solder joints, base pairs = Velcro; pairing rules =
keyed connectors (2-pin A–U, 3-pin G–C); one pair = one Velcro hook, a stack =
a strip; minimum loop = minimum bend radius of a cable.

#### Concept 3 — Secondary structure and dot-bracket notation (in progress)

Three levels of structure: **primary** = the sequence; **secondary** = the set
of base pairs (which position is wired to which); **tertiary** = the real 3D
arrangement. We work at the secondary level because it is cheap and reliable
to predict and captures most of what matters; 3D is far harder and outside
our compute budget. A secondary structure is a set of pairs (i, j) with
i < j. Pairs must be **nested or side-by-side, never crossing**. Crossing pairs
(**pseudoknots**) exist in nature, but standard folding tools exclude them, and
so do we (a limitation to state in interviews). Named parts: stem, hairpin
loop, bulge, internal loop, multiloop. **Dot-bracket notation** writes a
structure as a string the same length as the sequence: `(` = paired with a
later position, `)` = paired with an earlier one, `.` = unpaired. Because
pairs never cross, brackets match like parentheses in code, and a stack
(last-in, first-out) recovers the pairs. Example: `GGGAAACCC` / `(((...)))`.

Analogies used: primary = component list; secondary = netlist/schematic;
tertiary = physical layout. No-crossing rule = routing on a single metal
layer with no vias (arcs drawn above the sequence may not cross).
Dot-bracket = balanced parentheses in code.

#### Concepts 4 + 5 — Minimum free energy, and the design problem (taught as one block)

**Concept 4 (energy).** A sequence can fold in many valid ways; energy
decides which one it actually adopts. Every structure gets a free energy
ΔG (units kcal/mol; unfolded = 0; more negative = more stable). ΔG = ΔH − T·ΔS:
forming pairs releases energy (ΔH < 0, favourable), but pinning a floppy chain
into a fixed shape removes freedom (ΔS < 0, so −T·ΔS > 0, a cost). That's why
**stacks lower the energy and loops raise it**, and why heating melts
structures. The **nearest-neighbour model** computes ΔG as a sum of
local pieces (each stack, each loop), using experimentally measured tables
(Turner parameters). The **MFE structure** is the valid structure with the
lowest total ΔG. There are exponentially many structures, but because pairs
never cross, the problem splits into independent sub-stretches, so dynamic
programming (Zuker algorithm) finds the MFE in O(N³) time. *This is the real
reason tools exclude pseudoknots.* Toy tally (rounded Turner-style numbers:
G–C/G–C stack ≈ −3.3, hairpin loop of 3 ≈ +5.4): `GGGAAACCC` →
`(((...)))` ≈ −1.2 beats `.((...)).` ≈ +2.1 and unfolded 0.0. `GGGACCC` →
its only hairpin ≈ +2.1 > 0, so it stays unfolded; this answers the "allowed
vs. holds" question from concept 2. Thermal noise at body temperature
≈ 0.6 kcal/mol; rule of thumb: every ≈1.4 kcal/mol of energy gap ≈ 10× more
time in the lower structure. The gap between the best and second-best
structure acts like a **noise margin**. MFE is a *model's prediction*, not the
truth.

**Concept 5 (design).** Folding (sequence → structure) is the *forward*
problem, like simulation: one DP run. Design / **inverse folding**
(structure → sequence) is like synthesis. It is hard because: (a) the search
space is 4^N (N = 50 → ~10³⁰ sequences; at 10⁹ checks/s that's ~3,000× the
age of the universe); (b) the landscape is rugged: one letter change can
destroy a design (`GGGAAACCC` → `GGGAAACCA` removes pair (1,9), so the target's
best toy energy goes from −1.2 to +2.1 and the target is no longer the MFE);
(c) the target must beat *every* rival structure by a margin, not merely be
low; (d) the answer is a *set* (many valid sequences, or none), and we want
many diverse ones. The classical approach is local search with the folder in
the loop (e.g. RNAinverse: mutate, refold, keep if closer): slow per design,
gets stuck in local minima, and learns nothing between tasks. The generative
approach learns what natural RNA looks like from data, then samples many
candidates quickly, each checked by the folding software (the **oracle**).
Honest limitation: "success" means *the oracle predicts* the target, not a
wet-lab result.

Analogies used: ball on a shaking landscape (thermal noise); noise margin of
a logic gate (energy gap); static timing analysis (DP reuses per-node results
instead of enumerating exponentially many paths); simulation vs. synthesis
(forward vs. inverse); experienced designer vs. random trial-and-error
(generative vs. search).
