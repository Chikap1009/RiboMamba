### ~03:20 — Phase 1 concept block taught (§1.7 step 1)

Summaries for revision (full text in the chat; GLOSSARY entries added):

- **RNA family:** sequences descended from one ancestor, with different
  letters but the same structure and job. Evolution let the letters drift and
  kept the shape. **Covariation**: both sides of a pair mutate together
  (G–C → A–U), so identity drops while the structure stays. **Clan**: a group
  of related families.
- **Rfam:** ~4,000 curated families; seed alignment → covariance model →
  genome scan → "full" members. HF copy = 20 M full-region sequences with
  family + clan, no structure, DNA letters.
- **bpRNA-1m:** 102k sequences *with* structures from 7 sources, no family
  labels. TS0 (80 % identity split) vs bpRNA-new (family-disjoint): models
  score well on TS0 and drop on bpRNA-new (MXfold2, Sato et al. 2021;
  Szikszai et al. 2022, to verify before citing) — the literature's own
  measurement of family leakage.
- **Tokenisation:** one nucleotide = one token; vocabulary `<pad>=0,
  <mask>=1, <bos>=2, <eos>=3, A=4, C=5, G=6, U=7`. Why not k-mers/BPE.
  Specials reserved now so all three models share one embedding table.
  Non-ACGU sequences dropped (no `<unk>`).
- **Batching/padding:** `(B, L)` tensors; pad to the batch's longest;
  attention mask 1 = real, 0 = pad; the three meanings of "mask"; padding
  waste; dynamic padding and length bucketing.
- **Length vs VRAM:** weights + grads + Adam ≈ 16 bytes/param (tiny);
  activations ∝ B·L·d·layers + B·heads·L² (naive attention). Estimate for
  8 layers, d = 384, B = 64: L = 256 ≈ 2.7 GB, 512 ≈ 7.4 GB, 1024 ≈ 23 GB.
  Oracle O(N³) and MFE accuracy also favour a cap. Transformer baseline sets
  the cap.
- **Leakage:** random split puts siblings on both sides; family/clan-aware
  split doesn't. Identity filters miss low-identity family members
  (covariation). Audit: disjoint labels, no exact duplicates, MMseqs2
  near-duplicate check with a random-split control.

### 20:58 — Phase 2 begins: concept block, Part A (masked diffusion)

Delivered in chat while the scan runs. Part B (Transformer, attention,
RoPE, training machinery) follows after Phase 1's records close.

Summary for revision:
- **Generative model** = a probability distribution p(x) over sequences you
  can sample from; a lookup table is impossible (4^100 ≈ 10^60 entries), so
  p(x) must be factorised into learnable pieces.
- **Autoregressive** (chain rule, left to right): exact in principle, but
  each letter is chosen before its pairing partner exists; infilling and
  whole-structure conditioning are awkward; L sequential steps. Not
  "impossible" for RNA; that's why AR Mamba is a baseline (Phase 4).
- **Masked models (BERT)** see both sides but, trained at ~15 % masking,
  aren't generators. **Masked diffusion** = train at every masking level
  0–100 %, generate from 100 % masked by revealing gradually.
- **Forward process**: each position independently masked with probability
  1 − α_t; linear schedule α_t = 1 − t. `<mask>` is **absorbing** (enter,
  never leave). Rejected: uniform letter-swap noise (model can't tell which
  letters are corrupted; creates false pairs) and continuous Gaussian noise
  on embeddings (letters are discrete).
- **Reverse process / sampling**: from all-masked; step t → s reveals each
  masked position with probability (t − s)/t, drawing its letter from the
  model; revealed letters are frozen. N steps trade quality for speed; with
  few steps, partners revealed in the same step can't coordinate. Length is
  fixed before sampling (drawn from training lengths now; from the target
  structure in Phase 5).
- **Loss**: E_t E_z [ (1/t) Σ_{masked i} −log p_θ(x_i | z_t) ]. Masked
  positions only; 1/t puts every noise level on the same scale (≈ L ×
  average CE) and makes the loss an upper bound on −log p(x) (negative
  ELBO), so it's reportable in **bits per nucleotide** (2.0 = knows nothing
  about 4 letters). Worked example: masks at 2, 5, 9 of `GGGAAACCC`, t = 1/3,
  model probabilities 0.6, 0.5, 0.9 → 1.309 nats × 3 = 3.93 nats ≈ 0.63
  bits/nt.
- **Denoiser**: any network mapping L tokens to L distributions over
  A/C/G/U, seeing both sides; no time input (the masks reveal the noise
  level; theory says the optimal prediction doesn't need t); special tokens
  can never be predicted. Same diffusion, swappable backbone = the clean
  Transformer vs BiMamba comparison.

**Phase 2 concept block, Part B** (Transformer denoiser + training
machinery), summary for revision:
- **Embedding**: learned table, id → d-vector; `(B, L)` → `(B, L, d)`.
- **Attention**: q = W_Q x, k = W_K x, v = W_V x; scores q·k/√d_h;
  softmax → weights summing to 1; output = weighted sum of values. Worked
  example: weights 0.284/0.140/0.576 → output [2.012, 0.564]. √d_h keeps
  scores unit-scale so softmax doesn't saturate. Padding keys get −∞.
  Bidirectional (no causal mask). Multi-head = several independent
  questions, concatenated, projected by W_O; 4d² parameters. The L × L score
  grid is the shape of a base-pair matrix; Mamba has no such grid, which is
  the scientific question of Phase 4. Fused attention (PyTorch SDPA)
  never stores the grid: memory ~linear, compute still quadratic.
- **Position**: attention is order-blind. **RoPE** rotates each (q, k)
  pair at position m by angle mθ; the dot product then depends only on
  m − n (phasors: e^{jmθ}·conj(e^{jnθ}) = e^{j(m−n)θ}); a bank of
  frequencies θ_k = 10000^(−2k/d_h). No parameters (clean parameter
  matching); relative offsets are what matter for RNA motifs.
- **Block** (pre-norm): x + Attn(LN(x)), then x + MLP(LN(x)). LayerNorm =
  per-position standardisation plus learned scale/shift (like automatic
  gain control); MLP = d → 4d → GELU → d, 8d² parameters; residual = bypass
  path, so gradients flow through deep stacks. ≈ 12d² per layer: d = 384,
  8 layers ≈ 14.2 M.
- **Head**: final LN → linear d → 8 logits → specials set to −∞ → softmax
  over A/C/G/U.
- **Training machinery**: gradient descent + backprop; AdamW (per-weight
  adaptive steps + decoupled weight decay); warmup then cosine decay; bf16
  mixed precision (fp32 master weights); gradient-norm clipping (a
  limiter); EMA of weights (a low-pass filter) for evaluation and sampling;
  validation bits/nt on held-out families with fixed noise; checkpoints
  with config, git hash and seed; TensorBoard/CSV logs.
