### 14:03 — Phase 4 concept block, instalment 1 of 3 delivered (§1.7 step 1)

Delivered in chat, labelled CORE / DETAIL, everyday analogies first (memory
note; handoff §5), the Control Systems mapping offered as optional because it
is exact. No comprehension check (§1.4). Summary for revision:

- **Two ways to move information between positions.** Attention: every
  position scores every other (query·key → L × L grid → softmax weights →
  weighted average of values; Phase 2's 1, 0, 2 → 0.284, 0.140, 0.576 re-used).
  State-space model: one pass, carrying a fixed-size summary (the state)
  updated at each letter. Analogy: bank balance (fixed size, updated per
  transaction, cannot recover a single transaction) vs the full statement.
- **The update rule.** h_t = a·h_{t−1} + b·x_t, y_t = c·h_t; a = keep factor
  in (0, 1). Phase 2's EMA of the weights is a one-number instance
  (a = 0.9999). Worked on `GGGAAACCC` with x = "is it G?": at C7 (G3's
  partner) a = 0.5 leaves 0.11 of a 1.75 peak (leaked away over the loop);
  a = 0.9 leaves 1.78 but blurred. Memory ≈ 1/(1 − a) steps. Real layers run
  many states with different keep factors; one Mamba-2 layer at d = 384 holds
  98,304 state numbers (12 heads × 64 channels × 128).
- **Control Systems form (exact).** h′ = Ah + Bx, y = Ch + Dx; notation trap
  (textbook state x / input u ↔ Mamba's h / x); D = feedthrough; A forced
  negative (A = −exp(·)) → poles in the left half-plane, discrete keep factor
  a = e^{ΔA} inside the unit circle; Δ = step size (A = −1, Δ = 0.69 →
  a = 0.5), where instalment 2 starts.
- **Linear vs quadratic cost.** L steps vs L² pairs (256 → 65,536;
  1,024 → 1,048,576). Measured single block: 6.0 vs 3.8 ms at 256 (Mamba
  slower), 11.7 vs 21.7 at 1,024 (faster). Big-O describes growth, not the
  price at small L. At our cap, linear time buys no speed; every model gets
  the same steps and batches (P4), so any Mamba win must come from quality.
  Linear time would matter for the long RNAs cut in D-007.
- **Filter view.** With fixed a, b, c the model is an LTI filter: output =
  input convolved with the impulse response (1, 0.5, 0.25, …); check
  y_7 = 0.0625 + 0.03125 + 0.015625 = 0.109375, same as the recurrence.
  Analogy: a clap's fading echo. S4 trained this way (one big convolution).
  Weakness: every letter fades at the same rate, so the model cannot choose
  what to keep (e.g. pause forgetting across a loop). Fix = selection
  (instalment 2), which breaks the convolution trick → the scan.
- **First look at the question.** Grid: C7 looks straight at G3 in one hop.
  State: whatever C7 knows about G3 must survive A4–A6 inside one summary.
  Real partners can be 100+ letters apart.

### 14:25 — Instalment 2 of 3 delivered (§1.7 step 1)

Summary for revision:
- **Δ = how long you look at a letter.** Glance (small Δ): keep memory,
  ignore letter; long look (large Δ): wipe memory, write letter. Forgetting
  and writing are tied through one dial. ZOH for a, Euler (b ≈ Δ·B) in code.
- **Selection.** Δ_t = softplus(·), B_t, C_t computed from each position;
  A constant, a_t = e^{Δ_t A} varies. Loop numbers above. Selective memory
  keeps order (0.96 / 0.35 / 0.13). B ≈ key, C ≈ query, x ≈ value.
- **The scan.** Selection kills the single impulse response. Steps as pairs
  (a, u); two steps compose into (a₂a₁, a₂u₁ + u₂); associative → tree;
  receipt analogy; 8 rounds for 256. DETAIL: states kept in fast on-chip
  memory and recomputed in the backward pass.
- **A Mamba-2 layer.** in_proj (z, x, B, C, Δ) → width-4 causal convolution +
  SiLU → selective scan (12 heads × 64 channels × 128 state) → gate SiLU(z) +
  normalisation → out_proj; no separate MLP; parameter table above; 56 % of a
  Transformer block.
- **Mamba-2 and the hidden grid.** One A per head → state-space duality:
  y_t = Σ_{s≤t} (C_t·B_s)(a_{s+1}⋯a_t) Δ_s x_s, an attention-like grid
  computed in chunks, never stored. Constrained: one direction, no softmax,
  every keep factor in between multiplies in, built from a 128-number state.

Summary for revision:
- **Why both directions.** `<bos> ? G G A A A C C C <eos>`: the hidden letter's
  partner (C9) is 8 letters to its right; a left-to-right reader at position
  1 has seen only `<bos>`. In training masks fall anywhere; in generation
  letters appear in random order; an AR model never needs the right side.
- **BiMamba layer.** Shared in_proj → forward (conv, scan, gate) and backward
  (flip each sequence, conv, scan, gate, flip back) → add → shared out_proj →
  residual. **Padding trap**: flipping a right-padded row puts pads first in
  the backward scan, where they would write into the state; flip each
  sequence within its own length instead (`C A G G <pad> <pad>`).
- **Sharing options** (D-016, my choice, Chirag may veto): shared
  projections + own conv/Δ-bias/A/D/gate-norm per direction, 1,000,264 per
  layer, 14 layers (Vision Mamba, Caduceus pattern, adapted to Mamba-2);
  rejected: two full mixers (7 layers), one mixer both ways (no direction;
  GC vs CG stacks differ by 1.0 kcal/mol), alternating layers.
- **AR Mamba.** `<bos> x₁…x_L` → `x₁…x_L <eos>`, cross-entropy everywhere,
  exact likelihood (secondary vs diffusion's bound, P7), sampling with the
  `<eos>` length constraint (P5), 14 layers, 13,927,672 parameters.
  Two controlled comparisons: backbone (TF vs BiMamba, same objective) and
  generation order (BiMamba vs AR, same layers).
- **The question, precisely.** Stored numbers per layer: attention K + V
  ≈ 73,000 at a typical 95 letters (196,608 at 256); one Mamba-2 direction
  98,304; BiMamba 196,608 = 2 × 12 × 64 × 128 = 2 × 256 × 384. So at our
  lengths the difference is access, not size: content lookup after the
  question is known vs write-before-you-know with fading, no softmax.
  Nested pairs = brackets = a stack (favours lookup); literature: SSMs weaker
  at recall/copying (Arora et al. 2023; Jelassi et al. 2024). For Mamba:
  locality bias; Caduceus on DNA; our Transformer's defect ≈ random anyway.
- **Written prediction (before any Mamba model exists; not binding):**

**Surprise:** Mamba is slower per token on SHORT sequences. My first

inconsistent gain; defaults are easier to defend).

**What Phase 5 must deliver (CLAUDE.md §5; frozen protocol P3, P7):**

`eterna100_test` (75), `p_target`, energy gaps, diversity of successful

**Design questions to teach and settle (several are Chirag's calls):**
1. *How to give the model the target.* Candidate: a per-position structure
   symbol (`(`, `)`, `.`, or the richer loop types) embedded and added to the
   letter embedding. Identical for both backbones, so fair; it says whether
   a position pairs, not with whom. A pair-aware attention bias would help
   only the Transformer (asymmetric → rejected unless both get an
   equivalent).
2. *Classifier-free guidance.* Train with the structure hidden in a fraction
   of steps (a "null" structure); at sampling, push the conditional
   prediction away from the unconditional one by a weight w chosen on
   validation (`rfam_val`) by a rule written first (Ho & Salimans 2022;
   Schiff et al. 2025 for discrete diffusion). Read the 2026 caution paper
   (arXiv 2608.08082) before choosing.
3. *Steering with the folding oracle* (non-differentiable reward): SVDD-style
   look-ahead (Li et al. 2024), SMC, or clean-sample Metropolis–Hastings.
   Must be **budget-matched**: compare with best-of-N reranking that uses the
   same number of oracle calls, or steering "wins" by spending more folds.
   Steer with ViennaRNA only; EternaFold stays the independent check (D-013).
4. *Which backbones.* CLAUDE.md §3.2 asks about *controllability* too, so a
   conditional Transformer vs conditional BiMamba comparison is in scope;
   the AR model can be conditioned by a structure prefix
   (`(((...)))<sep>GGGAAACCC`), as Gautam et al. 2026 do. Scope and seeds to
   decide with the compute estimate.
5. *Train from scratch or fine-tune the Phase 4 checkpoints.* Fine-tuning
   (new structure embedding, a fixed number of steps) is ≈ 5–10× cheaper;
   from-scratch repeats the D-011/D-012 tuning (≈ Phase 4 again, 60–70 h).
6. *Reference points:* the native sequences (they solve `rfam` targets by
   construction), ViennaRNA's own `RNAinverse`, and the unconditional model
   sampled at the target's length (a floor).

structures = ViennaRNA MFE of ≈ 510 k sequences, ≈ minutes on 20 threads;
